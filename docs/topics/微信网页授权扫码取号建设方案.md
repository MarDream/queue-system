# 微信网页授权扫码取号建设方案

> 请先阅读 [完整需求文档](../完整需求文档.md) 以了解当前范围、状态定义与文档结构。

## 1. 文档定位

本文档用于记录排队叫号系统后续阶段中"微信内扫码取号 / 预约取号 / 排队查询"的建设方案，作为后续需求评审、接口设计、数据库扩展与实施排期的依据。

当前状态说明：

- 本方案属于后续规划，当前版本尚未实现
- 当前线上能力仍以手机号驱动的现场取号与排队查询为主
- 本文档不得作为"当前已上线能力"对外宣称

## 2. 建设目标

面向手机端用户新增微信内服务入口，使用户通过扫描二维码打开页面时，可优先在微信内完成网页授权认证，并基于认证后的公共用户身份完成以下能力：

- 预约取号
- 现场扫码取号
- 查询我的排队情况
- 查询我的预约记录
- 取消未完成预约或等待中的票号

建设目标强调两点：

- 用户侧身份与后台管理员登录体系隔离
- 在微信内尽量减少重复输入手机号，提高办事便捷性

## 3. 适用场景

### 3.1 微信内场景

- 用户通过大厅海报、窗口台卡、政务入口菜单等扫描二维码
- 页面在微信内置浏览器中打开
- 系统自动发起微信网页授权
- 完成公共用户身份识别后进入服务首页

### 3.2 非微信场景

- 用户通过手机浏览器直接访问链接
- 无法走公众号网页授权时，降级为手机号登录或短信验证
- 登录成功后仍使用统一的公共用户会话访问预约和排队能力

## 4. 方案边界

### 4.1 本方案包含

- 微信内网页授权登录
- 公共用户会话机制
- 公共用户资料绑定
- 预约取号与排队查询的身份打通
- 微信内与非微信内双通道访问策略

### 4.2 本方案不包含

- 管理后台账号体系改造
- 小程序端建设
- 微信支付
- 微信模板消息或订阅消息推送
- 多公众号、多租户统一运营平台

## 5. 前置条件

要落地微信网页授权，至少需要满足以下条件：

### 5.1 公众号与主体条件

- 正式环境应使用单位主体公众号承载，不建议使用个人公众号
- 开发联调阶段可先使用微信测试号验证 OAuth 流程
- 如需后续统一跨应用身份，可进一步接入微信开放平台并使用 `unionid`

### 5.2 域名与网络条件

- 需要公网可访问域名
- 建议全站启用 HTTPS
- 需要在微信公众平台配置网页授权域名
- 回调地址必须与配置域名一致

### 5.3 后端安全条件

- 后端安全保存 `AppID` 与 `AppSecret`
- OAuth `code` 换取令牌必须在服务端完成
- 需要建立独立于后台管理端的公共用户登录态

## 6. 总体设计

### 6.1 身份体系拆分

系统保留两套相互隔离的身份体系：

- 管理端身份：后台管理员、区域管理员、窗口人员
- 公共用户身份：预约人、扫码取号人、排队查询人

公共用户身份不得直接复用后台登录用户表与后台 JWT 方案，避免权限边界混乱。

### 6.2 推荐认证路径

推荐按以下优先级处理：

1. 微信内打开时，优先走公众号网页授权
2. 首次进入优先尝试 `snsapi_base` 静默授权，获取 `openid`
3. 服务端建立公共会话
4. 如用户资料未补齐，再引导绑定手机号、姓名、证件号或其他业务所需字段
5. 非微信内打开时，降级为手机号验证码登录

### 6.3 公共会话策略

建议后端建立面向 H5 用户的公共会话，推荐特征如下：

- 会话由服务端生成并保存
- 前端仅持有安全 Cookie 或短时令牌
- 会话内关联 `openid`、绑定手机号、最近访问区域等信息
- 会话用于预约、取号、查排队、查我的记录

## 7. 业务流程设计

### 7.1 微信内扫码取号流程

```text
用户扫码 -> 微信内打开 H5 页面
-> 前端检测微信环境
-> 跳转微信 OAuth 授权地址
-> 微信回调后端授权接口
-> 后端根据 code 换取 openid
-> 建立公共用户会话
-> 返回前端服务首页
-> 用户选择预约取号 / 现场取号 / 查我的排队
```

### 7.2 首次绑定流程

```text
用户完成静默授权
-> 系统发现未绑定手机号或实名信息
-> 前端展示资料补全页
-> 用户提交手机号和必要资料
-> 后端完成公共档案绑定
-> 后续访问直接复用公共会话
```

### 7.3 非微信降级流程

```text
用户在普通浏览器访问
-> 前端识别非微信环境
-> 展示手机号验证码登录
-> 后端建立公共用户会话
-> 用户继续办理预约或查询
```

## 8. 页面规划

建议将当前 `/appointment` 页面升级为统一移动服务入口，包含以下区域：

- 顶部身份区：展示登录状态、手机号脱敏信息、所属用户昵称或头像占位
- 快捷入口区：预约取号、扫码取号、我的排队、我的预约
- 当前排队卡片：显示正在等待或已叫号的票号状态
- 预约记录卡片：展示最近预约、待到场预约、可取消预约
- 空状态引导区：在无记录时提示用户选择业务或预约时间

页面打开逻辑建议如下：

- 微信内：先走自动认证，再渲染页面
- 非微信内：先判断公共会话，不存在则进入手机号登录

## 9. 后端接口规划

建议新增 `/api/public` 命名空间，避免与后台接口语义混用。

### 9.1 微信授权接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/public/wechat/oauth/start` | 生成并跳转微信授权地址 |
| GET | `/api/public/wechat/oauth/callback` | 处理微信授权回调并建立公共会话 |
| GET | `/api/public/session/me` | 获取当前公共用户会话信息 |

### 9.2 用户资料接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/public/session/bind-profile` | 绑定手机号及用户基础资料 |
| POST | `/api/public/session/logout` | 退出公共会话 |

### 9.3 预约与排队接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/public/business-types` | 获取移动端可预约业务列表 |
| GET | `/api/public/tickets/active` | 获取当前用户有效排队记录 |
| POST | `/api/public/tickets/take` | 创建现场取号 |
| GET | `/api/public/appointments` | 获取当前用户预约记录 |
| POST | `/api/public/appointments` | 创建预约 |
| POST | `/api/public/appointments/{id}/cancel` | 取消预约 |

## 10. 数据模型扩展建议

建议在现有模型上新增或扩展以下结构：

### 10.1 微信身份表

`wechat_user`

建议字段：

- `id`
- `openid`
- `unionid`
- `nickname`
- `avatar_url`
- `subscribe_status`
- `created_at`
- `updated_at`

### 10.2 公共用户档案表

`public_user_profile`

建议字段：

- `id`
- `wechat_user_id`
- `phone`
- `name`
- `id_card_no`
- `status`
- `last_login_at`
- `created_at`
- `updated_at`

### 10.3 公共会话表

`public_session`

建议字段：

- `id`
- `session_token`
- `public_user_profile_id`
- `wechat_user_id`
- `expires_at`
- `last_access_at`
- `created_at`

### 10.4 业务表关联扩展

建议为以下表逐步补充公共用户关联字段：

- `ticket`：增加 `public_user_profile_id` 或 `wechat_user_id`
- `appointment`：增加 `public_user_profile_id` 或 `wechat_user_id`

这样后续查询"我的排队"和"我的预约"时，不必仅依赖手机号作为唯一索引。

## 11. 权限与安全要求

- 公共用户会话与后台管理会话必须严格隔离
- `AppSecret` 仅允许后端保存，不得进入前端构建产物
- 回调接口必须校验 `state`，防止 CSRF
- 手机号、证件号等敏感数据需脱敏展示
- 若涉及实名预约，应补充风控与资料校验规则

## 12. 实施阶段建议

建议按以下顺序分阶段推进：

### 12.1 第一阶段：认证打通

- 接入微信网页授权
- 建立公共用户会话
- 新增公共用户资料绑定页
- 支持"我是谁"和基础登录态识别

### 12.2 第二阶段：预约与取号身份化

- 预约接口切换为基于公共用户身份
- 取号接口切换为基于公共用户身份
- 支持我的排队、我的预约

### 12.3 第三阶段：体验增强

- 微信通知或订阅消息
- 多区域大厅入口分流
- 预约到号提醒和材料提示

## 13. 验收标准建议

- 微信内打开页面可自动进入授权流程
- 首次授权后能建立稳定公共会话
- 首次绑定资料后可复用身份进行预约和排队查询
- 非微信环境仍可通过降级登录正常办理业务
- 同一公共用户可查看自己的预约和有效排队记录
- 不影响现有后台管理端登录与权限体系

## 14. 风险与注意事项

- 个人公众号不适合作为正式政务场景承载主体
- 微信网页授权依赖域名、回调配置与公众号能力，需提前申请和联调
- 若后续计划接入小程序，建议尽早统一公共用户档案模型
- 若仍沿用手机号作为唯一主索引，后续多端身份统一会受限
